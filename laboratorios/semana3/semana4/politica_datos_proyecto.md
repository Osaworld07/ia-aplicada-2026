# **Política de datos del proyecto — Sistema de registro de accesos**

## **1\. Alcance**

Esta política aplica a los datos utilizados en el proyecto de registro y análisis de accesos.  
D1 Nombre, D2 Correo electrónico y D3 Teléfono son datos personales.  
D4 Fecha de acceso y D5 Hora de entrada se consideran datos personales asociados al registro.  
D6 Área, D7 Empresa y D8 Motivo de acceso son datos no personales, aunque pueden convertirse en identificadores indirectos al combinarse con otros datos.

## **2\. Ciclo de vida**

El ciclo de vida comprende Captura, Almacenamiento, Uso, Compartición, Retención y Eliminación.  
El Administrador del sistema es responsable de la captura y el almacenamiento de los datos.  
El personal autorizado es responsable del uso y el Líder del proyecto de la compartición.  
El responsable de datos controla la retención y el Administrador de datos realiza la eliminación segura.

## **3\. Normativa aplicable**

El proyecto considera la LFPDPPP de México porque maneja datos personales de personas físicas.  
También se utiliza el NIST AI RMF como marco voluntario para identificar, evaluar y gestionar riesgos de IA.  
La Ley de IA de la Unión Europea se considera como referencia para los requisitos relacionados con sistemas de IA cuando resulte aplicable.  
La matriz de cumplimiento identifica las obligaciones y recomendaciones relevantes para el proyecto.

## **4\. Controles comprometidos**

Se informará a las personas sobre el tratamiento de sus datos y se recopilará únicamente la información necesaria.  
Los datos almacenados tendrán acceso restringido y medidas de protección adecuadas.  
Se mantendrá supervisión humana, evaluación de riesgos y revisión de posibles sesgos durante el uso.  
Antes de compartir información se aplicará anonimización cuando sea necesario y se establecerán plazos de retención y procedimientos de eliminación segura.

## **5\. Manejo de datos con herramientas de IA**

No se ingresarán a herramientas de IA datos reales que permitan identificar directamente a una persona, como nombres, correos electrónicos o teléfonos.  
Para realizar consultas se utilizarán datos ficticios, anonimizados o enmascarados cuando sea suficiente para la tarea.  
Antes de utilizar una herramienta externa se revisará qué información será enviada y se evitará compartir datos innecesarios.  
Si una tarea requiere información real, primero deberá eliminarse o transformarse la información que permita identificar a las personas.

## **6\. Revisión**

Esta política será revisada al menos una vez por semestre y cada vez que cambien los datos, herramientas o procesos del proyecto.  
El responsable de datos realizará la revisión y propondrá las modificaciones necesarias.  
El Líder del proyecto aprobará la versión actualizada antes de su aplicación.  
Los cambios deberán quedar documentados para mantener un registro de las versiones de la política.
